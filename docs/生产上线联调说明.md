## 1. 基线

联调只认这一版。

- 仓库：`NewLife.Cube.Nova`
- 分支：`main`
- 提交：`d126b6fc66e549953fa6680e97f5ff67abcc7711`（短 SHA `d126b6f`）

## 2. 宿主

临时宿主用 **CubeDemoNC**。本库是 Razor Class Library，不单独当站点跑。

| 项 | 要求 |
| --- | --- |
| 宿主 | CubeDemoNC（临时） |
| 启用 | `AddCube()` 之后调用 `UseNova` |
| 主题 | 魔方设置 `Theme` = `Nova`，`Skin` = `Nova` |
| 目标框架 | `net8.0`，与 [README](../README.md) 技术栈、`NewLife.Cube.Nova.csproj` 的 `TargetFramework` 一致 |
| 魔方核心 | `NewLife.Cube.Core` 6.15.2026.901（与 csproj 的 PackageReference 一致，Ace 对标用这一版） |

`Program` 与 README 相同：

```csharp
services.AddCube();

var app = builder.Build();
app.UseCube(app.Environment)
   .UseNova(app.Environment);
```

改完主题后重新登录。确认页面来自 `Views/Nova` 与 `*_Nova`。联调用未覆写的原装皮肤：宿主 `wwwroot` 里不要放同名 CSS、JS 或视图。测之前硬刷新，避免旧的 `?v=` 缓存。

## 3. 联调范围

2. 用同一账号、同一菜单对照 Ace（`NewLife.Cube.Core` 6.15.2026.901）：提交字段、确认、刷新、跳转与 Ace 一致。外壳、Tabler 和自绘下拉以规范为准。

桌面浏览器走完全表。第 3.1、3.6、3.7 再在真机（或同等手机宽度）走一遍。

通过的打勾。失败的写入第 4 章清单，写清页面、步骤、期望、实际、截图。

## 4. 闸门

按这个顺序走。上一步没有书面结论时，下一步不开始。

```text
测试出清单 → UX 定级 → 产品批包 → Cloud 修包 PR → 全量回归 → 交付审 → squash 合入 main
```

| 顺序 | 动作 | 产出 | 进入下一步 |
| --- | --- | --- | --- |
| 1 | 测试按第 3 章出清单 | 每条必测都有通过或失败；失败含页面、步骤、期望、实际、截图 | 第 3 章没有空项 |
| 2 | UX 定级 | 每条失败标成 P0、P1 或 P2，并写明是否阻断上线 | 清单上每条失败都有级别 |
| 3 | 产品批包 | 书面列出本轮要修的条目 | 只把批准的条目交给 Cloud |
| 4 | Cloud 修包 | 从 `d126b6f` 拉出的 PR，只含批准条目 | PR 正文写上清单编号 |
| 5 | 全量回归 | 第 3 章整表重走，并复测已修条目 | 已关缺陷不再出现；新的失败回到步骤 1 |
| 6 | 交付审 | 按第 6 章给出结论 | 通过之后才 squash 合入 `main` |

缺陷清单至少这些列：`编号`、`页面`、`步骤`、`期望`、`实际`、`截图`、`级别`、`是否批准`、`PR`、`回归结果`。

## 6. 验收

下面三条同时成立，才可以 squash 合入 `main`：

1. **缺陷**：没有未关闭的 P0、P1。P2 只保留第 5 章已写明的项，或产品明确记入下一轮。
2. **真机**：第 3.1、3.6、3.7 在真机上走通；第 3 章其余路径在桌面走通。关键路径是：登录并进入外壳与工作台、列表增删改查、多分类页签、枚举下拉选中当前值、登录图上传后在登录页看到结果、吸底栏不挡最后一个字段、浮标不挡行操作、暗色切换后仍可操作。
3. **一致**：本文步骤与 CubeDemoNC 上的界面一致。文档和界面不符时先记入第 4 章清单，由产品决定改文档还是改实现。

只替换了部分 CSS 或视图的宿主，另走 [宿主覆写与回归清单](host-override-checklist.md)。那份清单不代替本文的必测项。
